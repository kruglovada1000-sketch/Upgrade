# Правила работы с ohrana.tech

Этот файл — постоянная памятка для AI и разработчика перед изменениями сайта `ohrana.tech`.

## Архитектура

- Сайт — статический многостраничный проект на HTML/CSS/JS.
- Не переводить проект на React, Vue, Next.js или другой фреймворк без отдельного решения.
- Сохранять существующую структуру. Основные рабочие каталоги сайта — `/css`, `/js`, `/images`; существующий `/assets` не ломать.
- Не создавать новые корневые папки без реальной необходимости.
- Главная страница имеет отдельную логику шапки и уникальную кнопку «Основной сайт»; общие страницы нельзя механически приравнивать к главной.

## Безопасность изменений

1. Перед массовой правкой определить затрагиваемые HTML/CSS/JS-файлы.
2. Не удалять рабочий код только ради уменьшения файла.
3. Общие стили и JS менять осторожно: одна правка может затронуть десятки страниц.
4. После изменения проверить главную и минимум одну обычную внутреннюю страницу.
5. При крупной переделке иметь контрольную ветку/коммит для отката.

## Дизайн и мобильная версия

- Контролировать ширины примерно 360–390 px и desktop.
- Бургер-меню должно быть хорошо видно.
- Светлая и тёмная темы должны работать на всех страницах.
- На светлом фоне не использовать плохо читаемый золотой текст.
- На золотых плашках избегать белого текста с низким контрастом.
- У изображений и карточек сохранять плавные скругления и единый визуальный размер.
- Не растягивать и не обрезать важные части изображений без необходимости.
- Для WebP на сайте ориентир по весу — около 400 КБ или меньше, если качество позволяет.

## SEO

Для каждой индексируемой страницы проверять:

- один понятный `<title>` и отсутствие нежелательных дублей;
- один основной `<h1>`;
- meta description;
- canonical на чистый основной URL;
- отсутствие служебных query-параметров в sitemap;
- согласованность URL между HTML, sitemap, robots.txt и внутренними ссылками;
- отсутствие битых ссылок и потерянных страниц;
- корректные 301-редиректы при замене старых URL;
- alt у содержательных изображений;
- Schema.org там, где она реально соответствует странице.

Не применять спамные или манипулятивные SEO-приёмы.

## Что считать готовой правкой

Правка считается готовой только после проверки:

- страница открывается без 404;
- CSS/JS/изображения загружаются;
- меню и ссылки работают;
- мобильная версия не ломается;
- тема переключается, если страница использует общий переключатель;
- title/H1/canonical не получили случайный дубль;
- изменения не разрушили соседние страницы.
