# Установка JARVIS // KODA

## Что это

Это наша рабочая версия JARVIS для проектов `ohrana.tech` и `Upgrade`. Внутри остаётся оригинальный движок JARVIS, а поверх него автоматически накладываются наши правила, русская рабочая манера и контекст сайта.

## Что потребуется на компьютере

1. Node.js 20 или новее.
2. Google Chrome или Microsoft Edge.
3. Claude Code, установленный и авторизованный.
4. Микрофон.

ElevenLabs не обязателен. Без него JARVIS использует системное распознавание и голос браузера.

## Первый запуск

Открой терминал в папке проекта и выполни:

```bash
npm install
npm run setup
npm start
```

После запуска открой адрес, который появится в терминале, обычно:

```text
http://localhost:5173
```

Открывать нужно именно в обычном Chrome/Edge, не во встроенном окне редактора. Разреши доступ к микрофону и нажми `INITIALISE`.

## Режимы безопасности

Обычный запуск:

```bash
npm start
```

По умолчанию опасные действия ограничены. Это рекомендуемый режим для первых запусков.

Режим с разрешением действий через инструменты:

```bash
npm run bridge:writes
```

Не включай его постоянно. Он нужен только когда осознанно требуется управление браузером/телефоном или изменение данных.

## Что должно быть подключено позже

Для полноценной работы нам понадобятся MCP-инструменты Claude Code:

- GitHub — чтение и работа с репозиториями `ohrana.tech` и `Upgrade`;
- Chrome/browser tools — проверка живого сайта;
- Android — работа с телефоном;
- при желании поисковые и медиа-инструменты.

JARVIS читает локальные MCP-серверы из `~/.claude.json`. Если инструмент там не настроен, JARVIS его не увидит.

## Наши основные голосовые команды

Можно говорить обычным русским языком, например:

- «Джарвис, проверь ohrana.tech»;
- «Проверь мобильную версию»;
- «Найди битые ссылки»;
- «Сверь sitemap»;
- «Сравни main с живым сайтом»;
- «Проверь индексацию»;
- «Подготовь файлы для FileZilla»;
- «Покажи, что сейчас сломано».

Реальная возможность выполнить команду зависит от подключённых MCP-инструментов.

## Важно

JARVIS // KODA — не замена резервным копиям и проверке diff. Для рабочего сайта сохраняется наш процесс: маленькая правка, проверка, затем слияние/публикация.
