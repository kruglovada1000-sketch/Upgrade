# Skill: SEO audit for static websites

Цель: находить технические SEO-проблемы на статическом многостраничном сайте и выдавать конкретные исправления без спамных методов.

## Когда использовать

Используй этот workflow при:

- добавлении или переносе статей;
- изменении URL;
- обновлении sitemap/robots;
- появлении дублей title, H1 или canonical;
- проблемах с индексацией;
- массовых изменениях шаблона страниц.

## Порядок проверки

### 1. Инвентаризация URL

Собери список индексируемых страниц из:

- файлов HTML;
- `sitemap.xml`;
- внутренних ссылок;
- известных старых URL и редиректов.

Отдельно отметь страницы, которые существуют в файлах, но отсутствуют в sitemap, и наоборот.

### 2. Дубли и каноникализация

Для каждой страницы проверить:

- `<title>`;
- `<h1>`;
- `<link rel="canonical">`;
- meta description;
- URL с `/` и без `/`;
- `.html` и альтернативный directory URL;
- служебные query-параметры.

Если один материал доступен по нескольким URL, выбрать один основной URL и согласовать canonical/redirect/internal links/sitemap.

### 3. Индексация

Проверить:

- `robots.txt` не закрывает важные страницы;
- sitemap содержит только нужные индексируемые URL;
- canonical ведёт на доступную страницу;
- страница не содержит случайного `noindex`;
- старые заменённые URL перенаправляются 301, когда это уместно.

### 4. Контентная структура

Проверить:

- один основной H1;
- логичную иерархию H2/H3;
- title соответствует реальной теме страницы;
- description не является механическим дублем;
- нет нескольких страниц с практически одинаковой целью поиска без причины.

### 5. Внутренние ссылки

Найти:

- битые href;
- orphan pages;
- ссылки на старые URL;
- ссылки с ненужными query-параметрами;
- важные страницы, до которых слишком трудно добраться из навигации.

### 6. Изображения

Проверить:

- содержательные изображения имеют alt;
- размеры файлов разумные;
- изображение не грузится в сильно большем разрешении, чем отображается;
- современные форматы используются там, где это уместно.

### 7. Производительность

Использовать Lighthouse как диагностический инструмент. Особое внимание:

- LCP;
- CLS;
- блокирующие CSS/JS;
- тяжёлые изображения;
- лишние сторонние скрипты;
- кэширование статических ресурсов.

### 8. Формат результата

Каждая проблема должна содержать:

1. URL/файл;
2. что именно не так;
3. почему это важно;
4. конкретное исправление;
5. приоритет: critical / high / medium / low.

Не давать общие советы, если можно указать конкретный файл или URL.

## Запреты

- не генерировать keyword stuffing;
- не создавать doorway pages;
- не скрывать текст от пользователя;
- не плодить страницы ради количества;
- не обещать гарантированное первое место в поиске.
